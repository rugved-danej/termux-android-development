# Java Profiles & Runtime Architecture

The Java runtime system in `termux-android-development` (`tadev`) is engineered to provide maximum compilation stability, performance, and disk storage optimization on mobile Android hardware.

Every supported profile relies exclusively on packages from the official Termux stable repository (`openjdk-21`, `openjdk-25`, `openjdk-17`). Unstable third-party repositories such as `tur-repo` are completely bypassed.

---

## 1. The Dual-Layer Android Compilation Challenge

Building modern Android applications natively inside Termux requires navigating two distinct layers:

- Layer 1: Host Runtime (JAVA_HOME and PATH)
  Used by: Interactive Shell, CLI scripts, Gradle Daemon
  Focus: Fast startup, compact headers, G1GC throughput

- Layer 2: Gradle Compilation Toolchain
  Used by: Android Gradle Plugin (AGP), Kotlinc, D8/R8
  Focus: Bytecode stability (Java 17/21 bytecode target)

### Why Unsupported Host JDKs Fail
When developers run a cutting-edge host JDK (e.g. OpenJDK 25 or experimental builds) directly against certain versions of the Android Gradle Plugin (AGP 8.x), the build can crash with:
```
Unsupported class file major version 69
```
or fail when Kotlin compiler daemons or annotation processors (KSP, Dagger/Hilt) encounter unexpected JVM bytecode structures.

To solve this, `tadev` offers both Dual-JDK Combinations and Single-JDK Solos.

## 2. Official OpenJDK Runtimes (2026 Landscape)

### OpenJDK 21 LTS (Released September 2023) &bull; Recommended Default
- Status in 2026: The industry gold standard for Android application compilation. 100% verified compatibility across AGP 8.x and AGP 9.x.
- Key Features:
  - Virtual Threads (Project Loom): High-throughput lightweight concurrency for build pipelines.
  - Generational ZGC & G1GC Optimizations: Predictable low pause times under tight RAM constraints.
  - Record Patterns & Pattern Matching for Switch: Expressive Java language features.
  - Sequenced Collections: Deterministic order access (`getFirst()`, `getLast()`).
- Why It Matters for Termux: Zero bytecode conflicts with AGP, rock-solid stability, and lowest overall RAM and storage overhead.

### OpenJDK 25 LTS (Released September 2025)
- Status in 2026: The modern default LTS standard for general Java development.
- Key Features:
  - Compact Object Headers (Project Lilliput): Drastically reduces JVM object header memory overhead, saving significant RAM on Android.
  - Generational Shenandoah GC: Ultra-low pause time garbage collector for fast interactive execution.
  - Project Leyden AOT Optimizations: Quicker JVM startup and warm-up cycles.
  - Flexible Constructor Bodies (JEP 513): Allows statements before `super()` and `this()`.
- Why It Matters for Termux: Incredible host performance for shell tools and modern Gradle 9+ configurations.

### OpenJDK 17 LTS (Released September 2021)
- Status in 2026: Legacy LTS baseline. Minimum runtime required by Android Gradle Plugin 8.0+.
- Key Features:
  - Sealed Classes: Exhaustive domain hierarchy modeling.
  - Strong Encapsulation: Strict internal API enforcement.
- Why It Matters for Termux: Maximum compatibility when compiling legacy or unmaintained Android codebases.

## 3. Combinations vs. Solos

### Dual-JDK Combinations (`25+21`, `25+17`, `21+17`)
In a combination setup:
1. `JAVA_HOME` points to a modern host JDK (e.g. OpenJDK 25) for high-speed terminal execution.
2. In `~/.gradle/gradle.properties`, both host and target toolchain paths are registered:
   ```properties
   org.gradle.java.installations.paths=/data/data/com.termux/files/usr/lib/jvm/java-25-openjdk,/data/data/com.termux/files/usr/lib/jvm/java-21-openjdk
   ```
3. Gradle automatically picks OpenJDK 21 to compile the Android source code while running the Gradle daemon on OpenJDK 25.

Advantages:
- Fastest host CLI performance.
- Zero bytecode version warnings during builds.

Trade-offs:
- Requires keeping two full JDK packages installed (~500 MB - ~550 MB storage).

### Single-JDK Solos (`21`, `25`, `17`)
In a solo setup, a single OpenJDK package serves as both the Termux host environment and the Gradle compiler toolchain.

Advantages:
- Saves ~300 MB of internal storage: Consumes only ~220 MB - ~280 MB total.
- Zero Configuration Overhead: Single path in `PATH` and `JAVA_HOME`.
- Lowest RAM Usage: Fewer JVM packages and daemons running concurrently.

## 5. Senior Full-Stack Recommendation: Why OpenJDK 21 is Selected

As a full-stack senior developer evaluating mobile build environments, Profile `21` (Single OpenJDK 21 LTS Solo) is designated as the recommended default for the following architectural reasons:

1. Storage Conservation: Storage is a high-cost resource on mobile devices. Installing dual JDKs consumes over 550MB. Single OpenJDK 21 uses ~270MB, saving ~300MB instantly.
2. Android Low Memory Killer (LMK) Resilience: Spawning multiple JVM daemons increases resident memory pressure. A single unified OpenJDK 21 runtime drastically lowers overall memory footprint.
3. Flawless AGP Compatibility: Android Gradle Plugin 8.x and 9.x natively target Java 21 bytecode (class major version 65). D8, R8, Kotlin compiler daemons, and KSP operate with 100% compatibility.
4. Maintenance Simplicity: Single symlink structure, zero toolchain desynchronization, and zero third-party package repository hazards.

## 6. How to Switch Java Profiles

### Interactive Keyboard Chooser
Run:
```bash
tadev java switch
```
- Use `[Up]`/`[Down]` or `j`/`k` to navigate.
- Press `[Enter]` to apply and activate the profile.
- Press `[Tab]` to automatically open this guide in your Android device's browser without requiring `termux-api`.
- Press `[Esc]` to cancel.

### Direct Command Line
Switch instantly by profile ID:
```bash
# Switch to recommended default (Single OpenJDK 21 LTS)
tadev java switch 21

# Switch to high-performance dual-JDK (OpenJDK 25 host + OpenJDK 21 toolchain)
tadev java switch 25+21

# Switch to modern OpenJDK 25 solo
tadev java switch 25

# Switch to legacy OpenJDK 17 solo
tadev java switch 17
```

### Shell Alias Shortcut
After running `tadev setup`, the `use-java` helper function is available in your shell:
```bash
use-java 21
use-java 25+21
```
Running `use-java` with no arguments prints the current active profile and lists all available profiles.
